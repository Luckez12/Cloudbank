# HDHub4u 2.0.0 — replace old engines with WATCH-only flow

Apply providers/hdhub4u.js and manifest.json at repository root and refresh VUEO. No YAML or app changes. The old provider code has actually been replaced: approximately 152KB to 9KB. No old extraction engine or download fallback remains in the provider. Historical old test commands now run the current simple-flow suite; they no longer test removed internals.

Flow with shared metadata: (1) HTML search on https://new9.hdhub4u.cl/?s=TITLE, (2) chosen detail page, (3) one hdstream4u WATCH page, then return its published HLS URLs. Native HTTP only. If shared metadata is unavailable, try the existing shared metadata bridge for up to one second, then a TMDB request only if needed. No domain JSON, search API, multiple-domain attempts, HubCloud/HubCDN/Download/gates, mirror workers, 3.5s result collection, playlist/segment verification or seek probes. A single request is bounded at 4s and the run at 12s.

Title matching uses normalized title/original title before the release year; an explicit movie year mismatch is rejected. TV additionally requires a search result for the requested season and a WATCH anchor with explicit matching SxxEyy in its immediate parent. If this exact layout is absent, TV returns no result rather than guessing another episode. Not all current site layouts are verified by these fixtures. Only the first matching detail and WATCH are used. Fixed current domain intentionally avoids extra domain-discovery work; update it if the site moves.

Packer decoding is retained only to read player-published source URLs, not to execute arbitrary player JS. Return up to three distinct HLS URLs actually present in that one WATCH script. A single master therefore remains a single Auto link; this release does not split variants or invent resolution choices. sourceVerified=false: no media probe is done. Stream Referer/Origin/User-Agent identify the WATCH context. This saves discovery work but does not fix CDN throughput, expired signatures, buffering or file seek behavior. Direct R2 files cannot be returned because all direct-download paths were removed.

English/Malay sidecars are collected from track elements or simple player track objects already in received HTML. No extra caption requests, language guessing or waiting. Other/unknown languages and thumbnail tracks are rejected. Dynamically loaded subtitles absent from player HTML will not be available from this extractor.

Validation: the new suite covers movie search/detail/WATCH with exactly three requests, one metadata fallback request when required, explicit TV episode selection, wrong-title/year rejection, missing WATCH/stream, EN/MS sidecars, preserved media headers and absence of legacy/mirror/probe/WebView requests. npm run validate passes for 25 providers. Android source extraction/playback/scan latency require device testing. Test the same title and send the 2.0.0 debug log if it fails. No guaranteed sub-five-second scan or buffering cure is claimed.
