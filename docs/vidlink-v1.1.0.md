# VidLink v1.1.0 — consolidated original-session extraction

Apply APP-VUEO-WebView-Consolidated-Session-v5-TV-Mobile-No-YML.zip at the app repository root, build/install, then apply this ZIP at Cloudbank root and refresh. Both companion updates are required. Old app versions fail explicitly rather than falling back to unverified links. No YML or separate test provider.

One exact-ID original-page WebView now supplies both its actual API response and observed media. The separate provider API request, forced X-Playback-Environment header and locally generated request token are removed. Embedded NaCl is retained only to decode the captured public API token: original origin/type/path, encrypted TMDB ID and TV season/episode must match the requested route, and explicit response metadata conflicts are rejected. The server can still return a mislabeled audiovisual asset; route matching does not inspect the movie's frames.

The provider derives its expected media from that verified same-session response and mirrors the site's MP4/HLS/DASH proxy URL conventions. DASH uses the API's provided cookie with the site's base64url sc query format; it is not manufactured from an MP4 URL. Observed URLs must match media origin/path and upstream host from the captured API. Either native request interception or an actual successful fetch/XHR response is required; JSON-listed URLs, bare blob URLs and unobserved candidates do not qualify. Rotating signatures are allowed while using the actual observed URL.

Then one bounded native HTTP request validates the observed MPD/HLS manifest or initial MP4 range. MPD must contain MPD/Period/AdaptationSet/Representation and addressing structure, without DTD/entity declarations. MP4 requires valid status/type/file size/initial byte range; HLS requires a real playlist. HTML/JSON/428/invalid responses remain rejected. Native headers/cookies are reused where available; response-only observations use page/configuration defaults plus refreshed cookies. A manifest probe does not verify child segments, decoder compatibility or native playback. No additional subtitle URL is requested; API captions are forwarded with their group.

Diagnostics: SESSION, WEBVIEW_STATE (including documentStart), API_CAPTURE (response/verified route/media option counts), CANDIDATES (native/response/API matches and mp4/hls/dash/other counts), HANDOFF_HTTP (status/content classification). No token/cookie/body values are added to logs. Browser readiness is not a prerequisite and is not treated as native playback proof.

Validation: actual injected hook tests and provider mock tests passed. Recorded public movie/TV token fixtures were decoded; wrong ID/episode/origin, tampered tokens, explicit mismatches, unobserved URLs and incorrect media paths/hosts are rejected. MPD/HLS/MP4 probe paths and 428/HTML/invalid XML rejection passed with one WebView + one HTTP probe and no separate API/subtitle request. Cloudbank validator passed with 53 providers. Full Android compilation and phone playback remain unverified here. This is a consolidated implementation, not a guarantee against future site changes or native HTTP blocking.
